# Content To Scenes

Use this file when turning raw content into visual structure.

## Extraction

Extract:

- Audience: who needs to understand this quickly.
- Core claim: the one sentence the page should make memorable.
- Proof: metrics, screenshots, examples, commits, diagrams, or demos.
- Sequence: steps, lifecycle, before/after, or decision path.
- Boundaries: what the page should not imply.
- CTA: repository, article, resume, demo, or next action.

## Scene Patterns

### Slide Demo

1. Hero claim: title, subtitle, audience-facing value.
2. Problem: what is hard or broken.
3. Mechanism: how the product/system works.
4. Evidence: metrics, screenshots, or concrete artifact.
5. Outcome: user value and next action.

### Concept Flow

1. Input state.
2. Transformation layer.
3. Decision or governance layer.
4. Output state.
5. Risk/control notes.

### Architecture Map

1. Actors and entry points.
2. Runtime core.
3. State and storage.
4. Tool/external integrations.
5. Observability, permissions, and recovery.

## Writing Rules

- Replace generic headings with specific claims.
- Keep cards under 32 Chinese characters or 12 English words when possible.
- Use metrics only when they support a decision.
- Avoid decorative filler such as "innovation", "efficiency", or "empowerment" unless backed by a concrete mechanism.
